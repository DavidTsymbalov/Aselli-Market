# Aselli Market · 0.1 beta

Минимальный Telegram-магазин: приветствие и кнопка «Открыть магазин» в личном чате, мини-приложение с единственной надписью, SQLite. Каталог, корзина и оплата пока не реализованы.

## Быстрый просмотр

Нужен Python 3.11 или новее. Сторонних зависимостей нет.

```sh
python3 app.py --web-only
```

Откройте http://localhost:8000. `/health` проверяет HTTP-сервер, а не подключение бота к Telegram. Сервер выдаёт только страницу и health, исходники, токен и база через HTTP недоступны.

## Подключение бота

1. Скопируйте `.env.example` в `.env`.
2. В `BOT_TOKEN` укажите токен из @BotFather. Он хранится только в `.env`, который исключён из Git и Docker-образа.
3. Укажите `WEBAPP_URL`: публичный HTTPS-адрес страницы без входа в аккаунт. Для теста можно опубликовать папку `web` на статическом HTTPS-хостинге, либо направить HTTPS-туннель на локальный порт 8000. Сам бот работает через long polling, входящий webhook ему не нужен.
4. Запустите `python3 app.py` и отправьте боту `/start` в личном чате.

При запуске бот добавляет команду `/start` и кнопку «Магазин» в меню. Любое текстовое сообщение в личном чате возвращает приветствие с кнопкой мини-приложения. Данные пользователя берутся только из обновлений Telegram; клиентская страница ничего не записывает в базу.

Работать должен только один экземпляр бота. Если уже установлен webhook, приложение останавливается с сообщением, не удаляя чужие настройки автоматически. Для режима polling сначала отключите прежний webhook. После остановки программы бот перестанет отвечать; для постоянной работы нужен сервер.

## Сервер с Docker

```sh
docker compose up -d --build
docker compose logs -f
```

Настройте HTTPS reverse proxy перед `127.0.0.1:8000` и укажите его публичный адрес в `WEBAPP_URL`. Не включайте HTTP Basic Auth на странице мини-приложения. Docker хранит SQLite в томе `market-data`, перезапуск и пересборка контейнера данные не удаляют. Не используйте `docker compose down -v`, если база нужна. Для копии базы используйте SQLite backup API, а не копирование одного файла при активной записи. Docker-размещение не запускается автоматически из этого репозитория.

## База

Локальный файл: `data/aselli.sqlite3`. Таблицы создаются из `schema.sql`: `users`, `products`, `orders`, `order_items`, `bot_state`. Пока фактически заполняются только пользователи и позиция обработки обновлений. Цены хранятся целыми числами в минимальных денежных единицах. База и `.env` не публикуются в GitHub. В будущих версиях изменения схемы должны оформляться отдельными миграциями; `CREATE TABLE IF NOT EXISTS` не изменяет существующие таблицы.

В бете обработка сообщений не гарантирует exactly-once: при аварийной остановке между ответом Telegram и сохранением позиции возможен повтор приветствия. Для будущих платежей потребуется отдельная идемпотентная обработка.


```sh
git init -b main
git add .gitignore .env.example .dockerignore app.py schema.sql web Dockerfile compose.yaml README.md tests
git commit -m "Initial Aselli Market 0.1 beta"
git remote add origin https://github.com/DavidTsymbalov/Aselli-Market.git
git push -u origin main
```

Если в репозитории уже есть файлы, сначала клонируйте его и перенесите туда файлы проекта, сохранив существующие изменения. Не применяйте force push. GitHub хранит код, но сам по себе не запускает Python-бота.
